Answer `item_exists()` by the engine's kind sets: schema, domain, function, sequence and table answer through their own families, while the kinds Firebird has no objects for at all -- type, extension, tablespace, partition function, partition scheme and full-text catalogue -- answer `False` without running a query instead of raising. `index` still refuses by name, because indexes are read only under a table (`list_index_states`), so a bare name cannot be resolved and `False` would disguise the gap as absence. The three sets partition the `ItemKind` enum, and the async twin answers alike.

Carry the partition answer into `TableState`: both introspectors now build every table state with `partitioning=self.partition_state()`, so an unpartitioned relation holds a `PartitionState` whose `scheme` is `None` rather than `partitioning=None`. Both `get_partition_state` annotations are `PartitionState` (not `Optional[PartitionState]`), matching the body, which always returns `self.partition_state()`. A guard test pins the string `partitioning=None` out of `src` and `tests`, and the sync and async table-state cases assert the same empty-`PartitionState` shape.
