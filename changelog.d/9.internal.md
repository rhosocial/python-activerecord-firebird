The catalogue tests read every family through its statement factory, and CI installs core from `release/v1.0.0.dev30` now that core #127 has merged.

Every schema-object family now has the tests it was missing in the layer between the two that existed. The statements were pinned and the CLI was pinned against a fake, but nothing called the family methods themselves, so a rendering that was right could sit beside a parse that read a different alias and no test would notice: `test_introspection_family_parsers.py` reads each parser against a row shaped like its own projection, `test_introspector_catalogue_matrix.py` calls all fifteen families against a live server twice (the second pass proves the cache answers rather than the catalogue), and the CLI's async test now covers every advertised type instead of `tables` alone -- including the capability gate, so a family the connected server cannot answer exits 2 with the sentence it promises.

The coverage job prints `term-missing` and keeps `coverage.xml` with the run, so a gate failure names its lines in the job log rather than only in the XML Codecov consumes; `codecov.yml` states the project and patch thresholds instead of inheriting a moving default. A tautological assertion in the float-renderer test -- a call compared with itself -- is replaced by the spelling it was meant to pin.
