Wire the transaction `wait`/`no_wait` pair into `format_begin_transaction` and `format_set_transaction`: `supports_transaction_wait` answers `True` (both `SET TRANSACTION WAIT` and `SET TRANSACTION NO WAIT` prepare on Firebird 5.0.4 and 6.0.0) and each parameter renders its own spelling on both statements, while a default `BeginTransactionExpression()` no longer appends an explicit `WAIT` and renders `SET TRANSACTION READ WRITE` instead of `SET TRANSACTION READ WRITE WAIT`, matching Firebird's server-side default.
