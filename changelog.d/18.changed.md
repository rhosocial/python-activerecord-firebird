Split the single `IntrospectionSupport` protocol into core's four families -- `StructureIntrospectionSupport`, `OperationalStatsIntrospectionSupport`, `DataProfileIntrospectionSupport` and `DdlExtractionIntrospectionSupport`, each with an async twin -- and classify Firebird's capabilities per family rather than as one aggregate. `Structure` and `DataProfile` answer their probes and render their formatters; `OperationalStats` and `DdlExtraction` answer `False` everywhere and refuse every formatter by name, because Firebird keeps no collector relation and no rebuildable statement text, and those refusals stay apart from `FIREBIRD_NOT_IMPLEMENTED` because core's composition mixin keeps the members reachable. `supports_partition_info` is gone: the partition switch is `supports_partition_metadata_introspection`, resolved from Firebird's own mixin and read wherever the old probe was named. The introspectors also answer core's neutral object-state API -- `get_table_state`, `get_partition_state` (always `scheme=None`, since Firebird has no table partitioning), `list_index_states`, `list_constraint_states`, `list_sequence_states`, `list_schemas`, `list_derived_objects` and `item_exists` -- with core's state records instead of backend-specific shapes, and the CLI gains no `partitions` type.
