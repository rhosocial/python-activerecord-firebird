Add `FirebirdColumnTypeMixin` (`mixins/column_type.py`), the backend's answer to core's new `ColumnTypeSupport` protocol: all eighteen common Python types are answered, and five of them deliberately answer `None` -- `dict` (no released Firebird has a JSON *reading* function: `JSON_VALUE` / `JSON_QUERY` are tracker #5431, still pending in the v6 roadmap, `JSON_EXTRACT` answers `-804 Function unknown`, and the `->` / `->>` spellings the core renders for `json_path` / `json_value` answer `-104 Token unknown`) and `list` / `tuple` / `set` / `frozenset` (Firebird *has* array columns, but their bounds are part of the type in the grammar while core's `ArrayType` carries only a dimension count, and the `ARRAY[...]` constructor is refused), so a model field annotated one of those now fails at definition time with `ColumnTypeResolutionError` naming `UseColumnType` rather than mapping to a column whose operations cannot be rendered. Add `FirebirdJSONMixin` recording `supports_json_path()` / `supports_json_type()` as `False` -- without it a JSON path reached the core default and came back as `JSON_EXTRACT` wrapped in `JSON_UNQUOTE`. Compose core's `TrimMixin`, `LpadMixin` and `RpadMixin`: Firebird spells all three natively, so the shared defaults are the answer and no override is needed.
