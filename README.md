This is a backend implementation for [rhosocial-activerecord](https://github.com/rhosocial/python-activerecord).
It cannot be used standalone.

## Requirements

- **Python**: `>=3.11`
- **Core**: `rhosocial-activerecord>=1.0.0.dev0,<2.0.0`
- **Driver**: `firebird-driver>=2.0.0`
- **CI-tested server versions**: 5, 6-snapshot
- **Published**: PyPI `1.0.0.dev1`

Firebird 3 or newer is required in practice: the gate table below shows a
large block of features switching on at 3.0, including `IDENTITY`, native
`BOOLEAN`, CTEs, window functions, `FOR UPDATE` and generators-as-sequences.

## Quick Start

```python
from typing import ClassVar, Optional

from rhosocial.activerecord.base import FieldProxy
from rhosocial.activerecord.backend.impl.firebird.backend import FirebirdBackend
from rhosocial.activerecord.backend.impl.firebird.config import FirebirdConnectionConfig
from rhosocial.activerecord.backend.expression import CreateTableExpression
from rhosocial.activerecord.backend.expression.statements import (
    ColumnConstraint,
    ColumnConstraintType,
    ColumnDefinition,
)
from rhosocial.activerecord.backend.expression.types import IntegerType, VarCharType
from rhosocial.activerecord.model import ActiveRecord


class User(ActiveRecord):
    __table_name__ = "users"

    id: Optional[int] = None
    name: str
    email: str

    c: ClassVar[FieldProxy] = FieldProxy()


User.configure(
    FirebirdConnectionConfig(
        host="localhost",
        port=3050,
        database="/var/lib/firebird/data/myapp.fdb",
        username="SYSDBA",
        password="masterkey",
    ),
    FirebirdBackend,
)

dialect = User.__backend__.dialect
User.__backend__.execute(*CreateTableExpression(
    dialect,
    "users",
    columns=[
        ColumnDefinition(
            dialect, "id", IntegerType(dialect),
            constraints=[ColumnConstraint(dialect, ColumnConstraintType.PRIMARY_KEY,
                is_auto_increment=True)],
        ),
        ColumnDefinition(dialect, "name", VarCharType(dialect, 100)),
        ColumnDefinition(dialect, "email", VarCharType(dialect, 255)),
    ],
).to_sql())

user = User(name="Alice", email="alice@example.com")
user.save()
rows = User.query().where(User.c.email == "alice@example.com").all()
```

### Async

`AsyncFirebirdBackend` exposes the same API. Method names are identical; add
`await`.

```python
from rhosocial.activerecord.backend.impl.firebird.backend import AsyncFirebirdBackend
from rhosocial.activerecord.model import AsyncActiveRecord


class User(AsyncActiveRecord):
    ...


User.configure(config, AsyncFirebirdBackend)
rows = await User.query().where(User.c.email == "alice@example.com").all()
```

## Firebird-Specific Features

### Domains

Firebird domains are a first-class DDL expression, not a raw string. Build a
`CreateDomainExpression` and render it:

```python
from rhosocial.activerecord.backend.expression import CreateDomainExpression
from rhosocial.activerecord.backend.expression.types import VarCharType

User.__backend__.execute(*CreateDomainExpression(
    dialect,
    "email_address",
    VarCharType(dialect, 255),
).to_sql())
# CREATE DOMAIN "EMAIL_ADDRESS" AS VARCHAR(255)
```

`supports_create_domain()` and the rest of the `domain*` family gate on
Firebird 2.5, so domains are unavailable on 2.0.

### Generators (sequences)

`supports_create_sequence()` / `supports_sequence()` gate on Firebird 3.0.

### Stored procedures

Create them with `FirebirdCreateProcedureExpression`; Firebird has no
`CALL` support switch in this backend, so invoking one means a `SELECT ...
FROM proc(...)` in a `where()` string.

## Version Gates

Gates below are the versions at which this backend's own `supports_*`
switch returns `True`, probed at 2, 2.5, 3, 4, 5.
A version is the first probe at or above the real gate, so each is an
upper bound within one ladder step. Switches already `True` at the
oldest release carry no gate and are omitted.

| Min version | Capabilities that turn on |
|---|---|
| 2.5 | `alter_domain`, `comment_on`, `create_database`, `create_domain`, `create_exception`, `create_role`, `domain`, `domain_checks`, `domain_collation`, `domain_default`, `domains`, `drop_database`, `drop_domain`, `drop_role`, `exception`, `multiple_domain_alter_actions`, `roles`, `unnamed_domain_check_drop` |
| 3 | `alter_role`, `alter_user`, `as_cursor`, `auto_increment`, `autonomous_transaction`, `basic_cte`, `boolean_type`, `create_package`, `create_package_body`, `create_user`, `cte`, `data_type_boolean`, `database_triggers`, `drop_user`, `filter_clause`, `for_update`, `for_update_with_lock`, `identity_columns`, `offset_fetch`, `packages`, `recursive_cte`, `window_frame_clause`, `window_functions` |
| 4 | `data_type_firebird_decfloat`, `data_type_firebird_int128`, `data_type_firebird_time_without_time_zone`, `data_type_firebird_timestamptz`, `data_type_firebird_timetz`, `decfloat`, `for_update_skip_locked`, `lateral_join`, `skip_locked` |

## Known Limitations

- **No connection pooling.** `pool_size` and `pool_timeout` are accepted by
  the config class but not consumed by the backend.
- **No full-text search and no JSON.** `fulltext_index`, `functional_index`
  and `json_type` are `False` at every probed version. Do not plan on
  `MATCH ... AGAINST` or JSON operators.
- **No table partitioning.** `add_partition`, `attach_partition`,
  `detach_partition`, `partitioned_table_creation`, `list_table_partitioning`,
  `range_table_partitioning`, `hash_table_partitioning`, `subpartitioning` and
  `reorganize_partition` are all `False`.
- **No `IF EXISTS` / `IF NOT EXISTS` on most DDL.**
  `add_column_if_not_exists`, `drop_column_if_exists`, `drop_constraint_if_exists`,
  `if_exists_table`, `if_not_exists_table`, `drop_index_on_table` and
  `trigger_if_not_exists` are unsupported.
- Also unsupported: `on_conflict_clause`, `returning_alias`,
  `fetch_with_ties`, `fk_match`, `stored_generated_columns`, `explain_plan`.

## Testing

Tests require a reachable Firebird server and must run serially. CI runs
against `firebirdsql/firebird:5` and a `6-snapshot` build.

```bash
export PYTHONPATH=src:tests
.venv3.14-ubuntu26.04/bin/pytest tests/
```

The shared contract suite lives in
[python-activerecord-testsuite](https://github.com/rhosocial/python-activerecord-testsuite):

```bash
PYTHONPATH=tests .venv3.14-ubuntu26.04/bin/pytest \
  ../python-activerecord-testsuite/src/rhosocial/activerecord/testsuite/feature/
```
